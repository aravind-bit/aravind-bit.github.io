THE PRODUCT THESIS

The failure is not reading. It is losing context between reading and deciding.

Extraction tools turn documents into data. Search retrieves passages. Chat answers questions. Textent is designed to preserve the review itself: the source, consequence, action, reviewer disposition, and version history.

02
ARCHITECTURAL DECISIONS

The architecture is the product promise made enforceable.

  1. 01
    Move the workload off the request path

    Direct object upload, queue backpressure, and observable orchestration keep heavy document work out of a fragile synchronous API call.

  2. 02
    Preserve structure before adding semantics

    Validate DOCX/OOXML, extract ordered blocks, and create source-bound evidence anchors before chunking, retrieval, or model judgment.

  3. 03
    Give the model a bounded assignment

    A benchmark-selected Bedrock configuration may classify, group, rank, or explain candidates. It does not invent the source set or approve the outcome.

  4. 04
    Let evidence veto the model

    Source identity, location, quotation, schema, and allowed-claim checks must pass before a finding reaches the reviewer.

04
WHY AWS + BEDROCK

One operating environment for workload control, model access, and governance.

01

Serverless workload control

Scale intake, queues, orchestration, and workers independently for irregular document demand instead of paying for idle application compute.

02

Model choice under evidence

Bedrock provides a managed model boundary; Textent would benchmark candidates, pin one configuration, and version every pipeline change.

03

Cost is an architecture input

Presigned upload, admission limits, queue concurrency, explicit token ceilings, alarms, budgets, and a kill switch bound each job before scale.

04

Security shares the control plane

IAM, KMS, WAF, CloudTrail, CloudWatch, environment isolation, and infrastructure as code make trust controls reviewable with the system.

The AWS choice also matches the creator's established cloud-data delivery experience, reducing implementation and operating risk without making familiarity the sole decision criterion.
